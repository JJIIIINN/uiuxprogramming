# 13주차 사용자 테스트 기록 (양식 A–E)

초록집사 `물주기 알림 신청`의 작성 상태 복구 기능을, 서비스를 쓸 만한 사람에게 써 보게 하고 관찰한 기록입니다. 교안의 README 양식 A–E를 따릅니다.

> **기록 상태: P01 1차 테스트 → 관찰한 문제 수정(커밋 `fb1e9db`) → 같은 과업으로 2차 테스트까지 완료.** 관찰하지 않은 내용은 적지 않았고, 해 보지 못한 항목은 `미확인`으로 적었습니다.

- 구현 내용과 내가 직접 한 QA: [README의 13주차](../README.md#13주차-작성-상태-복구와-사용자-테스트) (참여자 테스트 기록은 이 파일에 따로 남깁니다)

## 양식 A · 테스트 계획서 · 과업지

- 서비스·주로 사용할 사람: 초록집사(반려식물 물주기 알림 서비스) · 식물을 처음 키우는 자취생·직장인, 물 주는 시기를 자주 놓치는 사람
- 확인할 질문:
  1. 새로고침 뒤 작성하던 내용이 남아 있다는 것을 알아차리는가? (같은 내용을 다시 입력하지 않는가)
  2. 아직 신청이 끝나지 않았다는 것을 알고 신청을 마저 끝내는가?
  3. 적던 내용을 버리고 새로 시작하려 할 때 방법을 찾고, 무엇이 지워지는지 이해하는가?
- 테스트 버전·배포 주소: 1차 = 커밋 `dd879f3`, 2차 = 커밋 `fb1e9db` · https://jjiiiinn.github.io/uiuxprogramming/
- 참여자 코드·서비스나 코드를 본 경험: P01(진행자의 친구) · 집에서 식물을 키움. 초록집사 화면과 코드를 본 적 없음
- 실제 참여 인원·진행자·기록자: 1명 · 진행자 본인 · 기록자 본인
- 테스트 날짜: 1차·2차 모두 2026-11-23 (1차 뒤 수정해 배포한 다음 같은 날 2차 진행)
- 기기·브라우저: 맥북 · Chrome
- 과업별 제한 시간·도움을 줄 기준: T1 3분, T2 6분 · 30초 넘게 멈추면 "지금 무엇을 찾고 있나요?"라고만 물음(도움 아님). 참여자가 방법을 묻거나 1분 넘게 나아가지 못하면 볼 곳이나 누를 버튼을 알려 주고 `도움 제공`으로 기록(결과는 `도움 후 완료`)
- 개인정보: 실제 이메일·전화번호 대신 테스트용 값을 쓰게 함. 참여자가 직접 입력하는 T2의 이메일은 `mint@example.com` (이메일 입력칸의 흐린 예시 `green@example.com`과 같으면 빈 칸을 입력된 칸으로 착각할 수 있어서 다른 주소로 정함)
- 과업지 수정 이력(1차 테스트 뒤, 2차부터 적용): 1차에서 화면이 아니라 과업 문장 때문에 생긴 혼동 2건을 고침. ① 1차 T2에서는 이메일로 `green@example.com`을 쓰게 했는데 입력칸 예시와 같아서 참여자가 "지운 게 안 지워졌나?" 하고 착각함 → `mint@example.com`으로 변경 ② 1차 T2 문장의 "이름을 모르는 식물"이 화면의 필수 항목 `식물 이름`(별명)과 충돌해 참여자가 이름 칸에서 망설임 → "종류를 모르는 식물"로 변경. 아래 T2 문장은 수정한 뒤(2차용)의 문장

### 과업 T1 — 대표 과업: 새로고침된 신청을 마저 끝내기

- 참여자에게 읽을 문장: "창가에 둔 몬스테라 화분의 물주기 알림을 신청하고 있었어요. 마지막 확인 화면까지 왔는데 화면이 새로고침됐어요. 작성하던 내용으로 알림 신청을 마저 끝내 주세요."
- 시작 화면·입력값: 진행자가 새 탭에서 배포 페이지를 열고 식물 이름 `몬스테라 몽이`, 종류 `몬스테라`, 자리 `햇빛 드는 창가`, 이메일 `green@example.com`, 문자 알림 체크·`010-1234-5678`, 알림 시간 `직접 정하기` 오전 7:30을 입력해 3단계(확인)까지 간 뒤 수신 동의에 체크해 둠. 과업 문장을 읽고 참여자에게 새로고침을 부탁한 순간을 00:00으로 기록. 내 식물 목록은 비어 있는 상태
- 진행자용 완료 기준: `물주기 알림 신청 완료` 화면이 열리고 `내 식물 목록`에 ‘몬스테라 몽이’가 보임. 같은 값을 다시 입력했는지는 재입력 횟수로 따로 기록
- 진행자가 볼 곳: 새로고침 직후 처음 보는 곳, 안내의 버튼(1차 `이어서 작성하기`, 2차 `안내 닫기`)을 누르는지 그냥 아래로 내려가는지, `알림 신청하기` 버튼을 찾는 데 걸리는 시간

### 과업 T2 — 다른 경로: 적던 내용을 버리고 처음부터 다시 신청하기

- 참여자에게 읽을 문장: "친구 화분의 물주기 알림을 신청하다가 화면이 새로고침됐어요. 그런데 다른 화분 내용을 잘못 적고 있었다는 걸 알았어요. 적던 내용은 버리고, 새 화분으로 처음부터 신청해 주세요. 새 화분은 종류를 모르는 식물인데 잎이 작고 통통하고, 빛이 적은 방 안에 있어요. 알림은 이메일로만, 저녁에 받고 싶어요. 이메일은 mint@example.com을 써 주세요."
- 시작 화면·입력값: 진행자가 새 탭에서 식물 이름 `덩굴이`, 종류 `스킨답서스`, 자리 `바람 통하는 베란다` → `다음`, 이메일 칸에 `green@exam`까지만 쓴 2단계(알림 받기) 화면. 과업 문장을 읽고 참여자에게 새로고침을 부탁한 순간을 00:00으로 기록
- 진행자용 완료 기준: `물주기 알림 신청 완료` 화면이 열리고 `내 식물 목록`의 새 식물이 `다육이 · 빛이 적은 방 안`, 알림 `저녁 8시`, 문자 없음으로 보임. 새 신청에 `덩굴이`·스킨답서스·베란다 값이 남아 있지 않음 (식물 이름은 참여자가 정함)
- 진행자가 볼 곳: 적던 내용을 지운 뒤 지워졌다는 것을 무엇을 보고 아는지, 확인 창 문구를 읽는지, 종류를 모를 때 무엇을 누르는지

## 양식 B · 진행 안내문

참여자에게 아래 문장을 읽고 시작합니다.

> 오늘은 이 웹페이지가 쓰기 쉬운지 알아보려고 합니다.
> 화면을 쓰면서 무엇을 하려는지, 어떤 결과를 예상하는지 말해 주세요.
> 막히면 말씀해 주세요. 원하면 언제든 멈출 수 있습니다.
> 기록에는 이름 대신 참여자 번호를 쓰겠습니다.

- 과업마다 양식 A의 시작 화면과 입력값을 다시 준비한 뒤, 과업 문장을 읽고 시작 시각을 적습니다.
- 클릭·발언·도움 요청이 나온 시각을 적습니다. 참여자가 멈추면 "지금 무엇을 하려고 하세요?"라고 묻습니다. 버튼 위치나 클릭 순서를 알려 줬다면 도움으로 적습니다.
- 완료했거나, 시간이 다 됐거나, 참여자가 멈추면 과업을 끝내고 바로 사후 질문(양식 D)을 합니다.

## 양식 D · 사후 설문·인터뷰

## 양식 E · 수정·재검증 기록지

화면을 고치기 전과 고친 뒤의 사용자 테스트를 나란히 적습니다. 기능을 다시 확인한 결과(회귀 QA)는 아래에 따로 적습니다.

관찰한 사실과 원인 가설을 나눠 적습니다. 원인 가설은 진행자의 해석이고, 2차에서 같은 과업으로 확인합니다.

**문제 U1 · 지운 뒤 지워졌다는 안내가 없고, 빈 1단계에 `임시 보관됨`이 뜸**

- 문제 ID·참여자·과업·관찰 시각: U1 · P01 · T2 · `지우고 다시 시작`을 누른 직후와 빈 1단계
- 실제 행동·발화: 빈 진행 줄을 보고 지워졌다고 짐작함. 빈 1단계의 `임시 보관됨 · 오후 4시 59분`을 보고 "뭐가 보관됐지?" 하며 잠깐 망설임. 사후 2번 4점 이유 "지운 뒤에는 ‘지웠다’는 말이 안 보여서 빈 진행 줄을 보고 짐작함"
- 가능한 원인 가설: 지우면 표시줄이 말없이 사라져 결과를 알려 주는 문구가 없음. 값이 없어도 1단계에 들어가면 진행 단계를 보관하면서 `임시 보관됨`을 띄움
- 사용자 영향·우선순위: 지워졌는지 확신하지 못하고 망설임. 과업은 끝냄. 상태 명확 점수가 깎인 유일한 이유라 1순위로 수정
- 후속 수정 항목·예상 변화: 지운 뒤 시작 화면에 `✓ 작성하던 내용을 모두 지웠어요. 처음부터 다시 작성할 수 있어요. 신청을 끝낸 식물은 내 식물 목록에 그대로 있어요.` 표시. 입력·선택한 값이 없으면 보관하지 않고 `임시 보관됨`도 띄우지 않음 → 지운 직후의 망설임이 없어지고, 지워졌다는 것을 안내 문구로 판단할 것으로 예상

**문제 U2 · 다시 작성하면 무엇이 지워지고 남는지 확인 창이 다 알려 주지 않음**

- 문제 ID·참여자·과업·관찰 시각: U2 · P01 · T1·T2 · 사후 질문 6번
- 실제 행동·발화: T1 "이메일까지 지워지는지는 확신이 없었음". T2 "이미 신청을 끝낸 식물 목록은 남을 것 같지만 확인 창에 그 말은 없음". T2에서 확인 창 문구는 읽고 `지우고 다시 시작`을 누름
- 가능한 원인 가설: 확인 창이 "식물 정보와 알림 설정, 임시 보관한 내용"이라고만 해서 이메일이 들어가는지, 신청을 끝낸 식물은 어떻게 되는지 알 수 없음
- 사용자 영향·우선순위: 지우기 전에 불확실함. 이번에는 그래도 진행함. 2순위
- 후속 수정 항목·예상 변화: 확인 창 문구를 `지금 작성하던 식물 정보와 알림 설정(이메일·전화번호·시간)이 모두 지워지고 되돌릴 수 없어요. 이미 신청을 끝낸 식물은 내 식물 목록에 그대로 남아요.`로 변경 → 사후 6번에서 지워지는 것과 남는 것을 확신 있게 답할 것으로 예상

**문제 U3 · `이어서 작성하기`를 꼭 눌러야 하는지 알 수 없음**

- 문제 ID·참여자·과업·관찰 시각: U3 · P01 · T1 · 복구 안내를 읽은 직후
- 실제 행동·발화: `이어서 작성하기`를 누른 뒤 아래의 `알림 신청하기`를 누름. 사후 1번 4점 이유 "내용이 이미 화면에 있는데 `이어서 작성하기`를 꼭 눌러야 하는지 몰랐고, 신청 버튼이 화면 아래에 있었음"

- 같은 참여자의 학습 / 다른 참여자의 경험 차이: 같은 참여자가 같은 날 같은 과업을 다시 해서 익숙해진 영향이 섞여 있음.
  - 참여자가 직접 말한 것: "두 번째라 복원 안내는 바로 이해했고 대신 새 식물 종류를 어떻게 고를지 보는 데 시간이 좀 걸렸어."
  - 수정한 곳에서 달라진 것: T2에서 지운 직후의 망설임이 없어짐, 사후 6번에서 이메일이 지워진다는 것을 확신 있게 답함, T1에서 다음에 할 일을 스스로 말함. 다만 참여자는 1차 T2에서 다시 작성과 확인 창을 이미 겪어 봤기 때문에, 6번 답이 바뀐 확인 창 문구 때문인지 1차 경험 때문인지는 가를 수 없음
  - 수정과 관계없이 그대로이거나 느려진 것: T1 수행 시간은 1차와 같음(약 28초). T2는 1차에 바로 찾았던 `생김새로 찾기`를 2차에는 잠깐 찾았음. 1차 문장은 "이름을 모르는 식물", 2차 문장은 "종류를 모르는 식물"이라 과업 문장 차이의 영향일 수도 있음
  - 다른 참여자와의 비교는 하지 못함(참여자 1명). 처음 보는 사람에게도 같은 결과가 나오는지는 미확인
- 미해결 문제·비교의 한계:
  - 고치지 않은 것: 생김새로 찾기 결과의 "기본 14일"과 확인 화면의 "17일마다"가 다른 이유를 설명하지 않음. `알림 신청하기` 버튼이 화면 아래에 있음(안내 문구로 위치만 알려 줌). 이메일 입력칸의 흐린 예시가 입력한 값처럼 보일 수 있음(과업지 주소를 바꿔 겹치지 않게만 함)
  - 2차에서 새로 본 것: 종류를 모를 때 넘어갈 수 있는 선택지를 찾느라 잠깐 살펴봄(T2 쉬움 4점의 이유). `안내 닫기`로 이름을 바꿔도 버튼을 누르고 지나감. 지운 뒤 안내와 확인 창의 "목록은 남아요" 문구가 실제로 읽혔는지는 확인하지 못함
  - 비교의 한계: 참여자 1명. 행동별 경과 시간은 재지 않아 전체 수행 시간으로만 비교함. 2차는 T2 과업 문장 2곳이 1차와 다름(과업지 수정 이력 참고). 1차에서 30초 넘는 멈춤과 도움이 없었기 때문에 2차에서 줄어들 수 있는 것은 짧은 망설임과 사후 응답의 불확실함뿐이었음. 1차와 2차를 같은 날 이어서 해서 기억이 그대로 남아 있었음
