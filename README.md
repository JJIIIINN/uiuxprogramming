# 초록집사

식물을 처음 키우는 사람을 위한 반려식물 돌봄 서비스 소개 페이지입니다. uiuxprogramming 과제로 만들었습니다.

- 배포 페이지: https://jjiiiinn.github.io/uiuxprogramming/
- 저장소: https://github.com/JJIIIINN/uiuxprogramming

## 서비스 개요

| 항목 | 내용 |
| --- | --- |
| 주요 사용자 | 식물을 처음 키우는 자취생·직장인, 물 주는 시기를 자주 놓치는 사람 |
| 서비스 목적 | 식물마다 알맞은 물주기 일정을 알려 줘서 반려식물을 시들지 않게 키우도록 돕기 |
| 사용자 목표 | 내 식물에 맞는 날짜에 물주기 알림 받기 |
| 핵심 행동 | 내 식물을 등록하고 물주기 알림 신청하기 |
| 완료 조건 | 식물 이름·종류·놓아둔 자리와 이메일·알림 시간을 조건에 맞게 입력하고(문자 알림을 켜면 휴대폰 번호도), 확인 화면에서 수신 동의에 체크한 뒤 `알림 신청하기`를 눌러 신청이 저장되면 완료 화면에 첫 알림 날짜가 표시됨 |

페이지 구성: 상단 바(메뉴) → 첫 화면 → 서비스 소개 → 주요 기능(탭 3개) → 이용 방법 → 물주기 알림 신청 → 내 식물 목록 → 자주 묻는 질문(아코디언) → 푸터 (+ 모달 2개)

## 13주차: 작성 상태 복구와 사용자 테스트

`물주기 알림 신청`을 작성하다가 최종 저장 전에 새로고침하면 처음으로 돌아가던 문제를 확인하고, 같은 탭에서 새로고침해도 작성하던 화면과 값을 이어서 쓸 수 있게 고쳤습니다.

- 사용자 테스트(양식 A–E), 수정, 재검증 기록: [docs/week13-user-test.md](docs/week13-user-test.md) — P01 1차 테스트 → 관찰한 문제 3건 수정(커밋 `fb1e9db`) → 같은 과업으로 2차 테스트. 요약은 아래 [3번](#3-사용자-테스트와-수정재검증)
- 아래 1·2번과 회귀 QA는 내가 직접 한 QA 기록이고, 참여자 테스트 기록은 위 파일에 따로 남깁니다.

### 1. 과업 기반 QA (개선 전)

대표 과업: **내 식물을 등록하고 물주기 알림을 이메일과 문자로 신청하기** (서비스의 핵심 행동)

| 항목 | 내용 |
| --- | --- |
| 시작 조건 | 12주차 버전(커밋 `95ed3b6`). Chrome 158(macOS), 창 너비 1100px. 페이지를 새 탭에서 열고, 신청 기록이 없는 상태(내 식물 목록 0개). `알림 신청`에서 `등록 시작하기` → 식물 이름 `몬스테라 몽이`, 이메일 `green@example.com`, 휴대폰 `010-1234-5678` 입력 |
| 선택 상태 | 종류 `몬스테라`, 자리 `햇빛 드는 창가`, `문자(SMS)로도 알림 받기` 체크, 알림 시간 `직접 정하기` 오전 7:30, `수신 동의` 체크, 3단계(확인) 화면 |
| 행동 | **`알림 신청하기`를 누르기 전에 새로고침**(⌘R 또는 F5) |
| 기대 결과 | 새로고침 뒤에도 확인 화면(3단계)이 그대로 보이고, 입력·선택한 값과 수신 동의가 남아 있으며, 아직 신청 전이라는 것을 알 수 있다 |
| 실제 결과 | 시작 화면(`내 식물 등록하고 물주기 알림 받기`)으로 돌아가고 진행 표시 네 칸이 모두 회색이 됨. `등록 시작하기`를 다시 누르면 식물 이름 `0 / 20자`, 종류 `선택해 주세요`, 자리 미선택이고, 이메일·문자 체크·휴대폰 번호·알림 시간·수신 동의도 모두 비어 있음. 내용이 사라졌다는 안내가 없음. 신청 기록은 0개(저장되지 않음) |
| 예상 사용자 영향 | 입력·선택 9가지를 처음부터 다시 해야 함. 화면이 아무 말 없이 처음으로 돌아가서 신청이 됐는지 안 됐는지 알 수 없고, `내 식물 목록`까지 내려가 확인해야 함. 휴대폰에서는 당겨서 새로고침이나 다른 앱에 다녀온 뒤 다시 불러오기로 쉽게 일어나는 상황이라, 다시 입력하지 않고 신청을 그만둘 수 있음 |
| 재확인 | 수정한 뒤 같은 값으로 3단계에서 새로고침해 입력값·선택값·요약·안내를 확인 (아래 2번의 `같은 과업을 개선 후 다시 실행한 결과`) |

- 직접 본 결과: 새로고침 뒤 빈 시작 화면이 열렸습니다. 같은 방법으로 1단계·2단계 작성 중에 새로고침해도 결과가 같았습니다(시작 화면, 빈 값).
- 원인(코드에서 확인): 신청 흐름의 값과 진행 단계가 화면과 JavaScript 변수에만 있고 어디에도 저장되지 않았습니다. `localStorage`에는 `알림 신청하기`에 성공한 신청만 저장합니다.

| --- | --- |

### 2. 작성 상태 복구 구현

**무엇을 보관하나** — 값을 입력하거나 고를 때, 단계가 바뀔 때마다 아래 내용을 한 묶음으로 보관합니다.

| 구분 | 보관하는 내용 |
| --- | --- |
| 입력값 | 식물 이름, 이메일, 휴대폰 번호, 직접 정한 알림 시간 |
| 선택값 | 식물 종류, 놓아둔 자리, 문자 알림 체크, 알림 시간, 수신 동의 체크 |
| 진행 단계 | 시작 · 1단계(내 식물) · 2단계(알림 받기) · 3단계(확인) 중 어디였는지 |
| 생김새로 찾기 | 찾기로 고른 식물인지, 찾기 영역이 열려 있었는지, 검색어와 검색 여부 |
| 보관한 시각 | 안내 문구에 "오후 2시 14분"처럼 표시 |

**어디에 보관하나** — `sessionStorage`의 `chorok-signup-draft`. 같은 탭을 새로고침하면 남고 탭을 닫으면 브라우저가 지웁니다. 이메일·전화번호가 들어 있어서 브라우저에 계속 남는 `localStorage`(신청 기록 `chorok-signups`가 쓰는 곳)와 나눴고, 다른 탭에서 새로 시작한 신청과 섞이지 않습니다.

**언제 복구하고 언제 지우나**

| 상황 | 동작 |
| --- | --- |
| 값을 입력·선택함, 단계를 이동함, 생김새로 찾기를 열고 닫거나 검색함 | 입력·선택한 값이 하나라도 있으면 임시 보관(아무것도 없으면 보관하지 않고 표시도 없음). 폼 위 표시줄에 `✓ 임시 보관됨 · 오후 2시 14분 · 이 탭을 새로고침해도 이어서 작성할 수 있어요.` |
| 같은 탭을 새로고침함 | 보관한 값을 다시 채우고, 값에 따라 달라지는 화면(문자 번호·직접 정한 시간 입력칸, 글자 수, 입력 확인 문구, 찾은 식물 안내, 확인 화면 요약)을 함께 되살린 뒤 작성하던 단계를 보여 줌 |
| 복구한 직후 | 파란 안내 상자: `↻ 작성 중이던 ‘몬스테라 몽이’ 알림 신청을 불러왔어요. 아직 신청이 끝나지 않았어요. 내용을 확인하고 아래 ‘알림 신청하기’를 누르면 신청이 끝나요.`(1·2단계는 `2단계 ‘알림 받기’부터 이어서 작성해 주세요.`) + `안내 닫기` · `처음부터 다시 작성`. 신청 영역을 보고 있었다면 안내가 보이게 화면을 맞추고 초점을 안내로 옮김 |
| `안내 닫기`를 누르거나 다른 단계로 이동함 | 안내 상자를 접고 임시 보관 표시만 남김 (누르지 않아도 그대로 이어서 작성할 수 있음) |
| `처음부터 다시 작성` | 값이 있으면 확인 창(12주차 `askConfirm` 모달을 다시 사용)을 먼저 띄우고, 확인 창은 지워지는 것(식물 정보, 이메일·전화번호·시간)과 남는 것(신청을 끝낸 식물 목록)을 알려 줌. `지우고 다시 시작`을 누르면 입력값·선택값·임시값을 모두 지우고 시작 화면으로 가서 `✓ 작성하던 내용을 모두 지웠어요. …` 안내를 보여 줌. `취소`·Esc면 그대로 |
| `알림 신청하기`로 저장에 성공함 | 신청 기록을 `localStorage`에 저장한 뒤 임시값을 지우고 입력칸도 비움. 완료 화면에서 새로고침해도 끝난 신청이 작성 중으로 되살아나지 않음 |
| 신청에 실패함(연결 끊김, 이미 신청한 식물, 저장 불가) | 임시값을 그대로 둠. 새로고침해도 확인 화면에서 다시 신청할 수 있음 |
| `신청하는 중…`(1.5초)에 새로고침함 | 저장되기 전이므로 확인 화면으로 복구. 신청 기록은 생기지 않음 |
| `신청하는 중…`에 `처음부터 다시 작성`을 누름 | 버튼을 잠가서 눌리지 않음. 보내는 중에 값이 지워지지 않음 |

**예외 처리**

- 보관한 내용이 깨져 있으면 무시하고 지운 뒤 시작 화면을 보여 줍니다.
- 목록에 없는 선택값(식물 종류·자리·시간)은 버리고, 앞 단계에 빈 칸이나 오류가 있으면 그 단계부터 보여 줍니다(빈 확인 화면이 열리지 않게).
- 브라우저가 저장을 막아 보관하지 못하면 `⚠︎ 이 브라우저에서는 작성 내용을 임시 보관할 수 없어요. 새로고침하거나 탭을 닫으면 입력한 내용이 사라져요.`라고 알리고 입력은 계속할 수 있습니다.
- 다른 영역(예: 자주 묻는 질문)을 보다가 새로고침했다면 보던 위치와 초점을 그대로 둡니다. 신청 영역으로 돌아오면 복구 안내가 보입니다.
- `자주 묻는 질문 > 등록한 식물은 어디에 저장되나요?` 답변에 임시 보관 설명을 더했습니다.

**복구하지 않는 것**: 항목 아래 빨간 오류 문구(`다음`을 누르면 다시 표시), 주요 기능 탭의 체험 입력값, 내 식물 목록의 필터 선택.

**주요 함수** (`script.js` 11번)

| 함수 | 하는 일 |
| --- | --- |
| `collectDraft()` / `saveDraft()` | 지금 화면의 값과 단계를 모아 보관. 완료 화면이거나 시작 화면에 값이 없으면 보관하지 않고 지움 |
| `restoreDraft()` | 페이지를 열 때 보관한 내용을 검사해 값·화면·단계·안내를 복구 |
| `clearDraft()` | 임시값 삭제. `restartSignup()`(다시 작성)과 `finishSignup()`(저장 성공)에서 호출 |
| `updateDraftBar(상태)` | 표시줄을 보관됨 · 복구 안내 · 지웠다는 안내 · 보관 불가 · 숨김으로 전환 |
| `askRestart()` | 값이 있으면 확인 모달을 띄운 뒤 다시 시작 |

**공통 JavaScript 함수와 이벤트 처리** (`script.js`의 1·9·10번)

| 함수 | 하는 일 | 쓰는 곳 |
| --- | --- | --- |
| `openModal(모달, 연 버튼)` / `closeModal(모달, 결과)` | 모달 열기(`showModal()`)·처음 초점 지정 / 닫기 | 모달 2개 모두 |
| `handleModalClose` | 모든 모달의 `close` 이벤트에서 스크롤 잠금 해제 → 연 버튼으로 초점 복귀 → 모달별 후속 동작 실행 | 모달 2개 모두 |
| `askConfirm({ title, text, okText, onConfirm, onCancel })` | 확인 모달의 제목·설명·버튼 문구를 바꿔 다시 쓰기 | 식물 삭제 (다른 확인이 필요해지면 이 함수만 부르면 됨) |

| `initTabs(탭 묶음)` / `selectTab(탭들, 고른 탭)` | 탭 묶음 하나를 동작하게 함 / 선택 상태와 내용 전환 | `[role="tablist"]`가 붙은 모든 탭 묶음 |
| `getMoveIndex(키, 지금 번호, 개수, 이전 키, 다음 키)` | 방향키·Home·End로 갈 번호 계산 | 탭(← →)과 아코디언(↑ ↓)이 같이 사용 |

- **이벤트 위임**: `data-modal-open="모달 id"`가 붙은 버튼은 어디에 있든 `document`의 클릭 하나로 처리합니다. 그래서 탭 안의 버튼과 아코디언 안의 버튼이 같은 모달을 엽니다. 닫기 버튼도 `data-modal-close`만 붙이면 됩니다. 아코디언·탭도 각 버튼이 아니라 묶음 하나에 `click`·`keydown`을 등록합니다.
- **HTML 약속만 지키면 추가 코드 없이 동작**: 새 모달은 `<dialog class="modal" id="…">`, 새 FAQ 질문은 `.accordion-item` 하나를 복사해 id만 바꾸면 됩니다.
- **값은 한 곳에서**: 계산 기준 모달의 표는 HTML에 숫자를 적지 않고, 신청 흐름이 쓰는 `waterDays`·`getWaterInterval()`로 채웁니다. 간격을 바꾸면 표도 같이 바뀝니다.

## 11주차: 웹 접근성 개선

시력이 약한 사용자, 색을 구분하기 어려운 사용자, 마우스 없이 키보드나 화면 낭독기로 이용하는 사용자도 정보를 이해하고 물주기 알림을 신청할 수 있도록 색·문구·키보드 조작을 고쳤습니다.

### 점검 방법

1. **자동 검사**: axe-core(WCAG 2.2 AA와 권장 규칙)를 1100px·390px에서 29가지 화면 상태마다 돌렸습니다. 처음 화면, 각 탭, 오류 안내, 식물 찾기, 신청 중, 완료, 신청 실패, 목록 없음, 필터 결과 없음, 모바일 메뉴 등을 포함합니다.
2. **키보드 점검**: 맨 위에서부터 Tab으로 끝까지 이동하며 확인했습니다. 초점 표시가 보이는지, 고정된 상단 바에 가려지지 않는지, 순서가 자연스러운지 봤습니다.
3. **키보드만으로 핵심 과업**: 마우스 없이 신청을 끝까지 진행해 봤습니다. 순서는 본문 바로가기 → 메뉴 → 탭 → 신청(찾기·오류 수정·조건부 칸·동의) → 완료 → 목록·필터입니다.
4. **대비 계산**: 바꾸기 전후 색 조합의 명도 대비를 계산했습니다.

이미 갖춰져 있어 점검만 한 것:
- 이미지 대체 텍스트: 서비스 소개 그림 1장에 내용을 설명하는 alt가 있습니다.
- 라벨 연결: 모든 입력칸·선택창에 `label`이, 라디오 묶음에 `legend`가, 도움말에 `aria-describedby`가 연결돼 있습니다(9주차).
- 제목 구조: h1 → h2 → h3 → h4 순서로 건너뛰는 단계가 없습니다.
- 안내 메시지: 오류 문구가 "문제 + 고치는 방법"으로 쓰여 있습니다(예: "이메일 주소 형식을 확인해 주세요. 예: green@example.com").

## 10주차: 메뉴 이동과 내 식물 목록

어디에 있는지 메뉴에서 바로 알 수 있게 했고, 알림을 신청한 식물을 물 줄 때별로 골라 볼 수 있는 `내 식물 목록`을 추가했습니다. 좁은 화면에서는 메뉴 버튼으로 메뉴를 열고 닫습니다.

### 이번 주 추가·수정한 기능

- **상단 메뉴**
  - `nav` 안의 `ul`·`li` 구조로 바꾸고 `내 식물 목록`을 추가해 메뉴를 5개로 만들었습니다.
  - 상단 바가 첫 화면에서만 고정되던 문제를 고쳐, 이제 페이지 어디에서나 화면 위에 보입니다.
  - 메뉴로 이동해도 제목이 상단 바에 가리지 않게 여백(`scroll-margin-top`)을 두었습니다.
- **현재 위치 표시**
  - 화면 위에서 35% 지점을 지난 마지막 영역을 현재 위치로 봅니다. 그 메뉴에만 `aria-current="location"`을 붙이고 다른 메뉴에서는 지웁니다.
  - 현재 메뉴는 파란 배경, 굵은 글씨, 아래쪽 막대(모바일은 왼쪽 막대)로 다른 메뉴와 구분됩니다.
  - 스크롤, 메뉴 이동(`hashchange`), 뒤로·앞으로 가기(`popstate`), 새로고침(`load`·`pageshow`) 때마다 실제 화면을 기준으로 다시 계산합니다. 그래서 표시가 항상 보이는 화면과 같습니다.
  - 맨 위 첫 화면에는 해당하는 메뉴가 없으므로 아무 메뉴도 표시하지 않습니다.
- **모바일 메뉴 (768px 이하)**
  - `메뉴 열기` 버튼을 누르면 메뉴가 상단 바 아래로 펼쳐집니다. 이때 버튼 문구는 `메뉴 닫기`, 아이콘은 ✕, `aria-expanded`는 `true`로 함께 바뀝니다.
  - 메뉴에서 목적지를 고르면 그 위치로 이동하면서 메뉴가 닫힙니다. `Esc` 키나 메뉴 바깥을 눌러도 닫힙니다.
  - 펼친 메뉴는 상단 바 아래에 겹쳐 뜨기 때문에, 열고 닫아도 페이지 배치가 밀리지 않습니다. 처음에는 메뉴가 페이지를 밀어내는 방식이었는데, 그때 브라우저가 스크롤 위치를 보정하면서 뒤로 가기 위치가 어긋나 이 방식으로 바꿨습니다.
  - 넓은 화면에서는 메뉴가 항상 보이고 버튼은 숨겨집니다.
- **내 식물 목록과 필터**
  - 알림 신청이 완료되면 식물이 `localStorage`에 저장되고 목록에 바로 나타납니다. 완료 화면에는 `내 식물 목록 보기` 버튼이 있습니다.
  - 각 식물은 물 줄 날이 가까운 순서로 보여 줍니다. 남은 날은 "물 줄 날이 1일 지났어요" / "오늘 물 주는 날이에요" / "4일 뒤 · 11월 7일(토)"처럼 문구와 색으로 표시합니다.
  - `오늘 물 줬어요`를 누르면 물 준 날을 오늘로 기록해 상태가 바뀌고, `삭제`를 누르면 목록에서 빠집니다.
  - 필터 버튼은 선택 표시(검은 배경과 ✓), `aria-pressed`, 목록 내용, 버튼 옆 개수, "전체 4개 중 ‘7일 안에’ 1개를 보여 주고 있어요." 안내가 함께 바뀝니다.
  - 목록이 비었을 때는 `예시 식물 넣어 보기`로 물 줄 때가 서로 다른 예시 식물 4개를 넣어 필터를 바로 시험할 수 있습니다.
- **신청 흐름 수정**: 한 사람이 식물을 여러 개 등록할 수 있게, 9주차의 "이미 신청함" 기준을 "같은 이메일"에서 "같은 이메일 + 같은 식물 이름"으로 바꿨습니다.

| 여유 있음 | 8일 이상 남음 | "○일 뒤 · 날짜" (파랑) |

| 상황 | 안내 | 다음 행동 |
| --- | --- | --- |
| 저장된 식물이 하나도 없음 (어떤 필터를 골라도) | "아직 등록한 식물이 없어요." + 요약 "등록한 식물 0개" | `알림 신청하러 가기`, `예시 식물 넣어 보기` |

- `오늘 물 줬어요`·`삭제`: `handlePlantAction()` 1379줄

### 조작 순서

1. **메뉴 이동**: 배포 페이지에서 상단 메뉴 `이용 방법`을 누릅니다. 해당 영역으로 이동하고, `이용 방법` 메뉴만 강조됩니다(`aria-current`).
2. **현재 위치 유지 확인**
   - 메뉴를 몇 개 더 누른 뒤 브라우저 뒤로 가기를 누르면, 이전 위치로 돌아가면서 강조도 따라 바뀝니다.
   - 새로고침해도 보이는 영역과 강조된 메뉴가 같습니다.
   - 직접 스크롤해도 강조가 따라 움직입니다.
3. **목록이 없을 때**: `내 식물 목록`으로 이동합니다. "아직 등록한 식물이 없어요." 안내와 `알림 신청하러 가기` 버튼이 보입니다. 이 상태에서 필터를 눌러도 같은 안내가 유지됩니다.
4. **주요 기능 이용**: `알림 신청하러 가기`(또는 메뉴 `알림 신청`)로 이동해 식물을 신청합니다. 예: 보스턴고사리, 햇빛 드는 창가 → 2일마다.
5. **결과 목록 확인**: 완료 화면의 `내 식물 목록 보기`를 누르면, 방금 신청한 식물이 "2일 뒤 · 날짜"로 목록에 나타나고 메뉴 강조는 `내 식물 목록`으로 바뀝니다.
6. **필터 선택**
   - `7일 안에`를 누르면 버튼이 선택 표시(✓)와 `aria-pressed="true"`로 바뀌고, 목록에는 그 식물만 남습니다. 이때 "전체 1개 중 ‘7일 안에’ 1개" 안내가 나옵니다.
   - `여유 있음`을 누르면 "‘여유 있음’에 해당하는 식물이 없어요." 안내와 `전체 보기` 버튼이 나옵니다.
7. **필터를 더 시험하기**
   - 예시 식물을 넣으려면 목록을 비운 상태(`삭제`)에서 `예시 식물 넣어 보기`를 누릅니다. 오늘 물 줄 식물 2개, 7일 안에 1개, 여유 있음 1개가 들어갑니다.
   - `오늘 물 줄 식물`에서 `오늘 물 줬어요`를 누르면 그 식물이 목록에서 빠지고 개수가 줄어듭니다.
8. **모바일 메뉴**: 화면을 768px 이하로 줄이거나 휴대폰에서 엽니다.
   - `메뉴 열기`를 누르면 메뉴가 펼쳐지고 버튼이 `메뉴 닫기`로 바뀝니다.
   - 메뉴를 고르면 그 위치로 이동하고 메뉴가 닫힙니다. `Esc` 키나 메뉴 바깥을 눌러도 닫힙니다.

## 9주차: 물주기 알림 신청 폼 개선

핵심 행동인 `물주기 알림 신청` 폼을 다듬어, 무엇을 입력해야 하는지 알고 잘못 입력한 값을 고쳐 신청을 끝낼 수 있게 했습니다.

### 이번 주 추가·수정한 기능

- **도움말과 label 연결**: 모든 입력·선택 항목에 `(필수)`·`(선택)` 표시와 입력 조건을 알려 주는 도움말을 달았습니다. 입력칸은 `label`(라디오 묶음은 `legend`)로 이름을 연결하고, 도움말·입력 중 표시·오류 문구는 `aria-describedby`로 연결했습니다.
- **선택에 따른 조건부 입력 (2곳)**
  - `문자(SMS)로도 알림 받기` 체크박스를 켜면 `휴대폰 번호` 칸이 나타납니다.
  - `알림 받을 시간`에서 `직접 정하기` 라디오를 고르면 `원하는 알림 시간` 칸이 나타납니다.
  - 숨겨진 칸은 `hidden`과 `disabled`로 입력·검사·신청 내용에서 빠지고, 표시돼 있던 오류도 지워집니다. 다시 나타나면 입력할 수 있고, 전에 입력한 값은 그대로 남아 있습니다.
- **입력하는 동안 상태 표시 (색과 문구를 함께 사용)**
  - 식물 이름: "1 / 20자 · 1자 더 필요"(주황) → "5 / 20자 · 조건 충족"(파랑) → "23 / 20자 · 3자 초과"(빨강)
  - 이메일: "확인 중: 아직 이메일 형식이 아니에요…" → "✓ 올바른 이메일 형식이에요."
  - 휴대폰 번호: 숫자만 입력하면 `-`가 자동으로 붙고, "확인 중: 지금 7자리 · 4자리 더 입력해 주세요." → "✓ 휴대폰 번호 11자리를 확인했어요."
- **오류 안내와 해제**
  - `다음`을 누를 때, 그리고 값을 입력한 칸에서 벗어날 때 검사합니다.
  - 한 번 검사한 항목은 입력하는 대로 다시 검사하므로, 올바르게 고치면 오류가 바로 사라집니다.
  - 오류마다 문제와 고치는 방법을 함께 알려 줍니다. 단계 아래에는 "수정이 필요한 항목 2개: 휴대폰 번호, 알림 받을 시간"처럼 고칠 항목을 모아 보여 주고, 첫 번째 항목으로 커서를 옮깁니다.
- **제출 처리**
  - `form`의 `submit` 이벤트로 처리합니다. 조건을 충족하지 못하면 다음 단계로 넘어가지 않습니다.
  - `알림 신청하기`를 누르면 1.5초 동안 "신청 내용을 보내는 중이에요."와 함께 버튼이 `신청하는 중…`으로 바뀌고 비활성화됩니다. `이전`·`수정`·수신 동의도 이때는 누를 수 없어, 여러 번 눌러도 한 번만 신청됩니다.
  - 성공하면 신청 기록을 브라우저 `localStorage`(`chorok-signups`)에 저장하고 완료 화면을 보여 줍니다.
  - 실패하면 입력 내용은 그대로 두고, 버튼이 `다시 신청하기`로 바뀌어 다시 시도할 수 있습니다.
- **다시 신청**: `처음부터 다시 신청하기`를 누르면 입력값, 글자 수·확인 문구, 오류와 안내, 조건부 칸, 버튼 문구, 진행 표시가 모두 처음으로 돌아갑니다. 저장된 신청 기록은 지우지 않습니다.

### 확인 순서

1. 배포 페이지 맨 아래 `물주기 알림 신청`에서 `등록 시작하기`를 누릅니다.
2. **빈 값 제출**: 아무것도 입력하지 않고 `다음`을 누릅니다. 세 항목에 빨간 안내와 "수정이 필요한 항목 3개" 안내가 나오고, 다음 단계로 넘어가지 않습니다.
3. **잘못된 값과 입력 중 표시**: 식물 이름에 `몽`을 입력하면 "1자 더 필요"와 오류가 나옵니다. `몽이`로 고치면 "조건 충족"으로 바뀌고 오류가 사라집니다. 20자를 넘게 입력하면 "○자 초과"가 표시됩니다.
4. 식물 이름은 2~20자로 맞추고, 종류와 자리를 고른 뒤 `다음`을 누릅니다.
5. **오류 수정**: 이메일에 `green@exa`를 입력하고 다른 칸을 누르면 형식 오류가 나옵니다. 이어서 `mple.com`을 입력하면 오류가 사라지고 "✓ 올바른 이메일 형식이에요."가 나옵니다.
6. **조건부 영역 (체크박스)**
   - `문자(SMS)로도 알림 받기`를 체크하면 휴대폰 번호 칸이 나타납니다.
   - 번호 없이 `다음`을 누르면 오류가 나옵니다. `01012345678`을 입력하면 `010-1234-5678`로 바뀌고 ✓가 표시됩니다.
   - 체크를 풀면 번호 칸이 사라지고 입력할 수 없게 됩니다. 다시 체크하면 입력했던 번호가 그대로 있습니다.
7. **조건부 영역 (라디오)**: `직접 정하기`를 고르면 시간 칸이 나타납니다. `오후 11:30`으로 `다음`을 누르면 시간 범위 오류가 나오고, `오전 7:30`으로 고치면 사라집니다. 다른 시간을 고르면 시간 칸이 사라집니다.
8. **정상 제출**
   - `다음`을 누르면 확인 화면에 문자 알림 번호와 `오전 7시 30분`이 반영돼 있습니다.
   - 수신 동의 없이 `알림 신청하기`를 누르면 안내가 나옵니다.
   - 동의하고 다시 누르면 약 1.5초 동안 `신청하는 중…` 상태(버튼 비활성)가 된 뒤 완료 화면이 나옵니다.
9. **다시 작성**: `처음부터 다시 신청하기` → `등록 시작하기`를 누르면 입력값, 글자 수, 안내 문구, 체크와 조건부 칸, 버튼 문구가 모두 처음 상태로 돌아갑니다.
10. **실패와 다시 시도**
    - 방금 신청한 것과 같은 이메일·같은 식물 이름으로 한 번 더 신청하면, 입력 내용은 그대로 둔 채 "‘○○’ 식물은 이 이메일로 이미 알림을 신청했어요" 안내와 `다시 신청하기` 버튼이 나옵니다.
    - `식물 이름·이메일 고치러 가기`로 이름이나 이메일을 바꾼 뒤 다시 신청하면 성공합니다.
11. (선택) 개발자 도구 Network에서 `Offline`으로 바꾸고 신청하면 연결 실패 안내가 나옵니다. 다시 `No throttling`으로 바꾸고 `다시 신청하기`를 누르면 성공합니다.

## 중간고사 추가 기능: 생김새로 식물 찾기

7주차 신청 흐름의 2단계(내 식물)에 **식물 종류를 모를 때 잎·줄기 생김새로 찾아 바로 고르는 경로**를 추가했습니다. "구멍 난 잎", "덩굴"처럼 생김새나 식물 이름을 입력하면 맞는 식물 목록이 나오고, 고른 식물이 신청 흐름의 식물 종류와 확인 화면에 반영됩니다.

- **사용자·목표와의 연결**: 주요 사용자인 식물 초보는 선물 받거나 사 온 식물의 종류 이름을 모르는 경우가 많습니다. 7주차 흐름에서는 종류를 모르면 2단계에서 막혀 목표(물주기 알림 받기)를 끝낼 수 없었습니다. 물주기 간격도 종류에 따라 달라지므로, 종류를 제대로 고르게 돕는 것이 알림의 정확도와도 이어집니다.
- **흐름과 연결한 지점**: 흐름의 중간인 2단계(내 식물)입니다. `식물 종류` 선택창 아래 `종류를 모르겠어요 · 생김새로 찾기` 버튼에서 시작합니다. 종류를 고르지 않고 `다음`을 누르면 나오는 오류 안내("종류를 모르면 아래 생김새로 찾기를 눌러 보세요.")도 이 기능으로 안내합니다.
- **입력과 버튼**: `식물 이름이나 잎·줄기 생김새` 검색창, 예시 검색어 버튼 5개(구멍 난 잎 · 덩굴 · 통통한 잎 · 하얀 꽃 · 가시), `찾기`, `이 식물로 선택`, `기타 관엽식물로 등록`(결과 없음일 때), `닫기`
- **찾는 방법**: 띄어쓰기를 무시하고 식물 8종의 이름 · 생김새 설명 · 검색어 목록과 비교합니다. 검색창에서 누른 Enter는 신청 흐름의 다음 단계로 넘어가지 않고 검색만 합니다. 한글을 조합하는 중에 누른 Enter는 무시해서 검색이 두 번 실행되지 않게 했습니다.

## 사용자 흐름: 물주기 알림 신청

페이지 맨 아래 `물주기 알림 신청`에서 시작부터 완료까지 다섯 단계로 진행합니다. 상단 메뉴의 `알림 신청`이나 첫 화면의 `물주기 알림 받기` 버튼으로도 바로 이동할 수 있습니다.

| 단계 | 화면 제목 | 사용자가 하는 일 | 다음 단계로 가는 조건 |
| --- | --- | --- | --- |
| 1. 시작 | 내 식물 등록하고 물주기 알림 받기 | 필요한 정보를 확인하고 `등록 시작하기` | 없음 |
| 2. 내 식물 (입력·선택) | 어떤 식물을 키우나요? | 식물 이름 입력, 식물 종류 선택(모르면 생김새로 찾기), 놓아둔 자리 선택 | 세 항목 모두 입력·선택 |
| 3. 알림 받기 (입력·선택) | 알림을 어디로 보내 드릴까요? | 이메일 입력, 문자 알림 선택(켜면 휴대폰 번호 입력), 알림 받을 시간 선택(직접 정하기를 고르면 시간 입력) | 이메일 형식이 맞고 시간을 고름, 나타난 칸도 조건 충족 |
| 4. 확인 | 입력한 내용을 확인해 주세요 | 입력 내용과 계산된 물주기 간격·첫 알림 날짜 확인, 필요하면 `수정`, 수신 동의 체크 | 수신 동의 체크 |
| 5. 완료 | 물주기 알림 신청 완료 | 결과 확인, 필요하면 `처음부터 다시 신청하기` | - |

- 진행 표시(`1. 내 식물 · 2. 알림 받기 · 3. 확인 · 4. 완료`)는 시작 다음 단계부터 현재 단계를 파란 막대와 굵은 글씨로, 지난 단계를 ✓로 표시합니다. 완료하면 네 칸이 모두 ✓로 바뀝니다.
- 물주기 간격은 `식물별 기본 간격 × 자리별 비율`로 계산합니다. 예를 들어 몬스테라(7일)를 햇빛 드는 창가(0.8)에 두면 6일마다입니다. 주요 기능의 `물주기 알림` 탭과 같은 계산 함수를 사용합니다.
